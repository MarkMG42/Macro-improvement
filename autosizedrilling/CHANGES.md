# Исправленная версия 1.1.0 — кандидат для проверки в SolidWorks

## Статус

Исходный VB.NET-проект не предоставлен. На основе логики из исходной DLL создан поддерживаемый C#-проект для того же .NET Framework 4.8/x64, с сохранением имени сборки, GUID класса и методов `SolidWorksMacro.main`/`Execute`. Это восстановленная реализация, а не точечная пересборка исходного VB.NET-проекта.

Оригинальный комплект в корне `autosizedrilling` не изменён. Сборка из `candidate/` предназначена для испытаний на копии чертежа. Совместимость загрузчика VSTA и фактические вызовы COM API нужно проверить в Windows/SolidWorks. Нельзя считать её проверенной заменой рабочей DLL до этих испытаний.

## Исправления

- Подсчёт распознанных отверстий отделён от уникальных X: шесть отверстий в двух рядах не превращаются в «3 X».
- Диаметры группируются отдельно, с допуском 0.001 мм по диаметру модели. Отдельная подпись для каждого диаметра.
- Поперечные размеры создаются для каждого уникального Y, а не только для первого отверстия. Порядок представителей стабилен при перестановке входных рёбер.
- Совпадающие кромки одинакового радиуса в одной проекции считаются одной позицией. Это количество распознанных проекций отверстий, не универсальный подсчёт физических отверстий в глубину или в сборке.
- Допуск позиций 0.05 мм задаётся в координатах модели и пересчитывается в масштаб листа. Недопустимый масштаб вызывает ошибку вместо подстановки 1:1.
- При распознавании проверяются полный оборот кругового ребра, направление его оси и наличие соседней внутренней цилиндрической грани. Круговая кривая сама по себе больше не считается отверстием. Проверка внутренней стенки использует `FaceInSurfaceSense`; её поведение на импортированных моделях требует натурной проверки.
- Концентрические распознанные окружности разных диаметров вызывают остановку: макрос не выбирает произвольно отверстие или зенковку.
- Выбор рёбер выполняется через выбранный `View.SelectEntity`, а не через выбор без контекста вида. Используется экземпляр SolidWorks, переданный VSTA.
- Для линейных и диаметральных размеров вызываются `AddHorizontalDimension2`, `AddVerticalDimension2`, `AddDiameterDimension2`. Для доступных дуговых привязок линейных размеров задаётся центр.
- Фактическое значение каждого созданного размера сравнивается с расчётной геометрией в метрах модели. При несовпадении новые размеры удаляются; в сообщении указаны ожидаемое и полученное значения. Существующие размеры не выбираются для удаления. Неудача удаления явно сообщается.
- Габариты учитывают экстремумы круговых рёбер, включая дуги, а не только подходящие горизонтальные/вертикальные линии. При отсутствии прямого ребра на действительной крайней границе макрос останавливается.
- Виды нескольких компонентов, сплайны/эллипсы и неподдерживаемые контуры отклоняются с пояснением. Поворот и косой торец автоматически не исправляются.
- Убран поздний вызов непроверенного `AutoArrangeDimensions`: размеры остаются на явно заданных уровнях с шагом 8 мм на листе.

## Проверки в этой среде

Сборка Release для `net48`, x64: 0 ошибок, 0 предупреждений. Исполняемые регрессионные проверки общей геометрической логики: 20 пройдено, 0 ошибок. Они проверяют реальные методы из `src/Geometry.cs`, подключённые в тестовый проект, без копирования реализации.

Покрыты один/два ряда, смешанные диаметры, одинаковый X с разными Y, двойные кромки, концентрические окружности, порядок рёбер, масштабы 1:1/1:10/1:100/2:1, дуги, наклонная ось окружности, косой торец, поворот, выступающий круговой контур, близкие диаметры, значение касательной вместо центра, недопустимый масштаб, отсутствие отверстий и центры вне границ.

Сборка проверяет наличие используемых методов в предоставленных interop DLL. Она не проверяет их фактическое поведение в SolidWorks. COM-выбор, условия дуговых привязок, удаление новых размеров, загрузка VSTA и распознавание цилиндрических граней в этой среде не исполнялись.

## Воспроизводимая сборка

Нужен .NET SDK 8.0 (проверено с 8.0.408). Reference assemblies .NET Framework 4.8 загружаются из NuGet; исходные interop DLL берутся из родительской папки. Из корня репозитория:

```sh
dotnet build autosizedrilling/src/AutoSizeDrilling.csproj -c Release
dotnet run --project autosizedrilling/tests/GeometryTests.csproj -c Release
```

Результат сборки: `autosizedrilling/src/bin/Release/net48/AutoSizeDrilling.dll`. В `candidate/` включена соответствующая тестовая сборка и её собственный portable PDB. Старый PDB из корня к ней не подходит. Проект не зависит от Visual Basic runtime, но по-прежнему требует SolidWorks и его interop DLL.

## Обязательная проверка перед использованием

Откройте копию модели и чертежа в своей версии SolidWorks. Загружайте кандидата отдельно через поддерживаемый вашей установкой механизм VSTA; не перезаписывайте единственную рабочую копию. Если загрузчик требует исходный VSTA-проект, понадобится оригинальный проект или адаптация штатного шаблона VSTA под этот C#-код.

| Сценарий | Ожидаемый результат |
| --- | --- |
| Прямой профиль, один ряд одинаковых отверстий | Те же значения, что при ручной простановке до центров |
| Два ряда по три отверстия одного диаметра | Подпись «6 X», три позиции X, два размера Y |
| Отверстия Ø8 и Ø10 | Две отдельные подписи с правильным количеством |
| Масштабы 1:1, 1:10 и 1:100 | Одинаковые значения в мм и число распознанных отверстий |
| Два вида одной модели на листе | Размеры привязаны только к выбранному виду |
| Окружность и круглый выступ | Выступ не считается отверстием; проверка распознавания на данной модели |
| Зенковка, совпадающие окружности | Нет произвольного выбора диаметра; неоднозначность распознанных концентрических окружностей вызывает остановку |
| Косой/повёрнутый вид, несколько компонентов | Понятный отказ, без размеров по случайному контуру |
| Искусственно вызванное несовпадение привязки | Новые размеры отменены, прежние размеры сохранены |

Для точной диагностики первоначальной жалобы всё ещё нужен проблемный чертёж со связанными моделями и ожидаемым/полученным значением. Скрытые отверстия, пересекающиеся отверстия, пазы, конические отверстия, неполные окружности, разрывы вида и специальная геометрия не покрыты натурными проверками; это не универсальный распознаватель всех типов отверстий. Повторный запуск добавляет новые размеры; обнаружение уже существующих размеров пока не реализовано.
