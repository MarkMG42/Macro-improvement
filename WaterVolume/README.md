# WaterVolume

Планируемый макрос SolidWorks для расчёта массы сборки с водой в трубопроводе.

Статус: описание задачи и проектирование. Исполняемого макроса пока нет.

## Задача

1. Получить массу всей сборки из массовых характеристик SolidWorks в активной конфигурации.
2. Определить внутренний объём элементов, содержащих воду, с учётом количества их экземпляров в сборке.
3. Для элементов, объём которых определить не удалось, использовать явно обозначенный запасной расчёт по проходу основной трубы.
4. Рассчитать массу воды и прибавить её к массе сборки.
5. Показать исходную массу сборки, объём и массу воды, итоговую массу, список приближений и нерассчитанных элементов.

## Единицы и формулы

`m_воды [кг] = V_воды [м³] × ρ_воды [кг/м³]`

`m_итого [кг] = m_сборки [кг] + m_воды [кг]`

Согласовано: полное заполнение, плотность 1000 кг/м³. Один литр соответствует одному килограмму воды. Для первой версии используем это значение по умолчанию с возможностью изменить плотность.

Для прямого цилиндрического прохода: `V = π × D_внутр² / 4 × L`.

Ду (DN) обозначает условный проход, а не гарантированный внутренний диаметр. Для точного расчёта нужны фактический внутренний диаметр либо наружный диаметр и толщина стенки. DN300 нельзя молча подставлять как точный диаметр 300 мм.

## Принципы реализации

- Объём металла из массовых характеристик детали не является объёмом воды.
- Для открытых труб внутренняя полость сама по себе не является замкнутым твёрдым телом. Нужны распознавание прохода и его границ либо подготовленные параметры/тело объёма жидкости.
- Наружный габарит детали не является внутренним объёмом. Для отводов, тройников и арматуры нужна отдельная геометрическая обработка или заданный объём.
- Каждый экземпляр учитывается отдельно в своей конфигурации; нельзя просто складывать уникальные файлы деталей. Подавленные компоненты не участвуют, а недоступные и облегчённые требуют явной обработки.
- Нужно исключить двойной подсчёт полостей в подсборках и уже смоделированной воды в исходной массе сборки.
- По умолчанию рассматриваются все компоненты, кроме исключений пользователя. Перед запуском пользователь должен иметь возможность выбрать исключения. Сухие элементы, например опоры и крепёж, следует исключать из расчёта воды; геометрический алгоритм не должен считать их наружный габарит полостью.
- Исключение из расчёта воды не вычитает собственную массу компонента из исходной массы всей сборки.
- Приближённый объём показывается отдельно от геометрически рассчитанного. Пропущенные элементы не должны превращаться в нулевой объём без предупреждения.
- Начальный сценарий — расчёт и отчёт без изменения геометрии и автоматического сохранения сборки.

## Согласованный сценарий расчёта

1. До запуска указать компоненты, которые не содержат учитываемой воды.
2. Для остальных попытаться автоматически определить внутренний объём.
3. Если это не удалось, предложить пользователю ввести внутренний объём вручную, применить приближение по проходу основной трубы либо явно исключить компонент из расчёта воды. Пример: для теплообменника можно ввести известную вместимость или проигнорировать его водяной объём.
4. Приближение: `V_детали = (π × D_внутр_основной_трубы² / 4) × L_детали`. Это площадь прохода, умноженная на длину; эквивалентно объёму воды на единицу длины трубы, умноженному на длину детали.
5. Читать параметры для конфигурации конкретного экземпляра. Подтверждённый источник — текстовое свойство конфигурации `Наименование`, пример ниже. Отдельное свойство длины и формат имени конфигурации пока не предоставлены; не угадывать их. При конфликте параметров или неизвестных единицах выводить проблему.
6. Внутренний диаметр сначала определять автоматически. Ручной ввод предлагать только при невозможности определить его автоматически на начальном этапе. Не заменять фактический диаметр значением DN без явного решения пользователя.
7. Если для приближения неизвестна длина детали, не подставлять габарит или длину другой трубы молча: оставить элемент нерассчитанным и предложить ручной объём либо исключение.
8. В отчёте различать автоматический объём, приближение по основной трубе, ручной объём, исключение пользователем и нерассчитанный элемент. Сумму с неразрешёнными элементами обозначать как неполную; явные исключения перечислять как границу расчёта.

Согласовано: основную трубу для запасного расчёта выбирает пользователь, в том числе при нескольких диаметрах в сборке. Диаметр брать у выбранного экземпляра в его конфигурации; сначала пытаться определить автоматически и только при неудаче предлагать ручной ввод. Этот диаметр применяется исключительно к нераспознанным деталям, для которых выбран запасной расчёт. Собственные распознанные размеры остальных компонентов сохраняют приоритет. Выбранную трубу и использованный диаметр указывать в отчёте; не выбирать их молча по максимальному диаметру или первому компоненту.

## Подтверждённый пример свойства конфигурации

Свойство: `Наименование`, тип: `Текст`.

Значение и вычисленное значение: `Отрезок трубы ЭСВ 219х6,0 L = 200 мм`.

Разбор для прямой трубы:

- наружный диаметр: 219 мм;
- толщина стенки: 6,0 мм;
- длина: 200 мм;
- внутренний диаметр: `219 − 2 × 6 = 207 мм`;
- внутренний объём: `π × 0,207² / 4 × 0,200 ≈ 0,006730705 м³`, или примерно 6,730705 л;
- масса воды при 1000 кг/м³: примерно 6,730705 кг на экземпляр.

Это расчёт по указанным размерам цилиндрической трубы, а не подтверждённое измерение полости модели. Для применимости нужно убедиться, что геометрия соответствует описанию и проход не имеет заглушек или внутренних вставок. Правило нельзя автоматически переносить на отводы и тройники.

При реализации разбор должен принимать десятичную запятую, проверять положительные размеры и условие `2 × толщина < наружный диаметр`. Другие разделители и форматы добавлять по явно поддерживаемым правилам; неоднозначный текст отклонять. Дублирование значения в строке экспорта не означает два экземпляра детали. Завершающий столбец `0` не является размером и в расчёт не входит.

## Осталось уточнить

1. Другие варианты `Наименование`, отдельные свойства размеров (если есть) и формат имени конфигурации для резервного чтения. Доступ к свойству пока не проверен на реальных моделях.
2. Откуда брать длину сложной нераспознанной детали, если в её свойствах нет пригодной длины. Выбор основной трубы пользователем определяет запасной диаметр, но не длину этой детали.
3. Версия SolidWorks и структура типовых сборок; для проверки нужны представительные модели и ожидаемые результаты.

## Порядок разработки и проверки

1. Согласовать правила на примерах прямой трубы, отвода, тройника и нераспознанной детали.
2. Реализовать обход сборки и отчёт по экземплярам, конфигурациям и источникам объёма.
3. Добавить расчёт поддерживаемой геометрии и согласованный запасной расчёт.
4. Проверить формулы и единицы на независимых эталонных значениях.
5. Проверить в SolidWorks прямые трубы, повторные экземпляры, подсборки, разные конфигурации, подавленные и недоступные компоненты, сложную арматуру и нераспознанные детали.
6. Сопоставить массу исходной сборки с интерфейсом SolidWorks и проверить отсутствие изменений модели после расчёта.

Критерий готовности: отчёт объясняет вклад каждого элемента, не скрывает приближения и неполноту, а результаты подтверждены на эталонных моделях. Одна только успешная сборка кода не подтверждает корректность расчёта в SolidWorks.
